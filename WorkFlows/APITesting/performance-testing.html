Performance API Testing

Starter scenarios for load, stress, and endurance API testing that learners can automate later with k6/JMeter.

1) Baseline Latency Check

Measure average response time under light traffic.

curl -s -w "\nTime: %{time_total}s\n" "https://api.open-meteo.com/v1/forecast?latitude=35&longitude=139¤t=temperature_2m"

2) Burst Traffic (Load Test)

Check whether API remains stable for short, concurrent bursts.

seq 1 30 | xargs -I{} -P 10 curl -s -o /dev/null -w "%{http_code}\n" "https://jsonplaceholder.typicode.com/comments/{}"

3) Stress to Failure Threshold

Gradually increase virtual users and capture first error/timeout point.

k6 run stress-test.js

4) Soak / Endurance

Run a long-duration test to identify memory leaks and performance drift.

k6 run --duration 30m --vus 20 soak-test.js
